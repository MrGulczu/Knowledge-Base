# Network Models

## Overview

Network communication can look like one large process in which data leaves one computer and somehow reaches another. In reality, many different operations must happen before data can be transmitted, delivered, understood, and finally presented to the user.

Network models divide this process into separate layers. Each layer has its own responsibilities and handles a specific part of communication.

This makes networking easier to understand, but more importantly, it makes networking easier to troubleshoot.

Instead of treating communication as a black box, we can identify which stage of communication is failing and investigate the corresponding layer.

Two models are commonly used when describing network communication:

* OSI model
* TCP/IP model

The OSI model divides communication into seven layers and is especially useful for learning, describing, and troubleshooting networks.

The TCP/IP model uses fewer layers and more closely represents how networking protocols are organized and implemented in real environments.

Understanding these models is not primarily about memorizing layer numbers. The goal is to understand what happens at each stage of communication and how those stages interact with each other.

## Why Network Models Exist

Before data can travel across a network, it needs to go through multiple stages.

For example, data generated by an application eventually has to become something that can physically travel through:

* copper cables,
* optical fiber,
* or wireless radio signals.

When data is received, the opposite process happens. Physical signals are interpreted and gradually transformed back into information that an application can understand.

Network models provide a standardized way of describing this process.

Without this separation, network communication could appear as a single large black box:

```text
Application → Network → Destination
```

With network models, we can look inside that process:

```text
Application
    ↓
Transport
    ↓
Network
    ↓
Data Link
    ↓
Physical transmission
```

Each layer adds its own information and provides specific functionality.

This separation is especially useful during troubleshooting. If we understand which layer is responsible for a particular function, we can narrow down where a problem is occurring instead of checking unrelated components.

## OSI Model

The OSI model consists of seven layers:

```text
7 - Application
6 - Presentation
5 - Session
4 - Transport
3 - Network
2 - Data Link
1 - Physical
```

The layers can be viewed as stages through which data travels.

When sending data, communication generally moves from Layer 7 toward Layer 1.

When receiving data, the process is reversed and moves from Layer 1 toward Layer 7.

## Layer 1 - Physical

The Physical layer is responsible for transmitting raw bits through a physical medium.

At this layer, logical information must be represented in a form that can physically travel between devices.

Depending on the medium, data may be represented as:

* electrical signals,
* light pulses,
* radio signals.

Examples of technologies and components associated with Layer 1 include:

* copper cables,
* fiber-optic cables,
* wireless radio communication,
* connectors,
* network interfaces,
* transceivers,
* link speed and signal characteristics.

The main question at Layer 1 is:

> Can the signal physically travel between both sides?

Typical Layer 1 problems include:

* disconnected cable,
* damaged cable,
* damaged connector,
* dirty optical fiber,
* faulty transceiver,
* weak wireless signal,
* wireless interference,
* interface without physical link.

If Layer 1 is not working, communication cannot continue to higher layers.

## Layer 2 - Data Link

Layer 2 is responsible for communication across the local network link.

One of the most important concepts at this layer is the MAC address.

A MAC address identifies a network interface at Layer 2 and allows Ethernet devices to determine where frames should be delivered.

Data at Layer 2 is commonly called a **frame**.

An Ethernet frame contains, among other information:

* source MAC address,
* destination MAC address,
* information identifying the encapsulated protocol,
* payload,
* error-detection information.

### Switching

Switches operate primarily at Layer 2.

A switch learns which MAC addresses are reachable through which ports by examining the source MAC address of frames it receives.

For example:

```text
Frame arrives on port 3
        ↓
Source MAC:
AA:AA:AA:AA:AA:AA
        ↓
Switch learns:
AA:AA:AA:AA:AA:AA → Port 3
```

When another frame needs to be sent to that MAC address, the switch can use its MAC address table to forward the frame to the appropriate port.

If the destination MAC address is not yet known, the switch performs **unknown unicast flooding** and forwards the frame through other relevant ports in the same VLAN.

This allows the destination to respond, which also allows the switch to learn its location.

### Switches and Hubs

A hub does not understand Ethernet frames or MAC addresses.

A hub is essentially a Layer 1 repeater. It receives a signal on one port and repeats it through other ports.

A switch can understand Layer 2 information and make forwarding decisions based on MAC addresses.

The main question at Layer 2 is:

> Which device on the local network should receive this frame?

Typical Layer 2 troubleshooting may involve checking:

* MAC address tables,
* VLAN configuration,
* switch ports,
* Ethernet frames,
* ARP or neighbor information,
* Layer 2 link status.

## Layer 3 - Network

Layer 3 introduces logical addressing and communication between different networks.

The most common Layer 3 protocol is IP.

Data at this layer is commonly called a **packet**.

MAC addresses are mainly useful for communication across the current Layer 2 link. IP addresses allow communication to continue across multiple networks.

When a workstation wants to communicate with another IP address, it determines whether the destination belongs to the local network.

If the destination is local, the workstation can communicate with it directly through the local Layer 2 network.

If the destination is outside the local network, the workstation forwards the traffic toward a router, usually its default gateway.

### Routing

Routers operate primarily at Layer 3.

A router examines the destination IP address and checks its routing table to determine the next hop or outgoing interface.

It does not normally determine the entire path from source to destination at once. Each router independently decides where to forward the packet next.

For example:

```text
Workstation
Destination IP: Remote server
        ↓
Frame:
Workstation MAC → Gateway MAC
        ↓
Router
        ↓
Layer 2 frame removed
        ↓
Destination IP examined
        ↓
Routing table checked
        ↓
New Layer 2 frame created
        ↓
Packet forwarded to next hop
```

The IP packet continues toward its destination, while the Layer 2 frame changes as the packet moves between different network links.

This creates an important distinction:

```text
Layer 2
Local link delivery

Layer 3
Communication between networks
```

The main question at Layer 3 is:

> Can the packet reach the destination network?

Typical Layer 3 troubleshooting may involve:

* IP address configuration,
* subnet mask or prefix,
* default gateway,
* routing table,
* routing protocols,
* reachability of remote networks.

## Layer 4 - Transport

Layer 4 determines how data should be transported between communicating systems.

Two of the most common protocols are:

* TCP,
* UDP.

### TCP

TCP is connection-oriented and designed to provide reliable, ordered communication.

It uses mechanisms such as:

* sequence numbers,
* acknowledgements,
* retransmissions,
* flow control.

TCP is useful when receiving the complete data correctly is important.

Examples include many:

* web connections,
* file transfers,
* remote administration sessions,
* email protocols.

### UDP

UDP is connectionless and provides much less transport overhead.

It does not provide built-in:

* delivery guarantees,
* ordering guarantees,
* retransmission of lost data.

This can be useful when receiving new information quickly is more important than waiting for missing older information.

Real-time communication is a good example.

If a small piece of live audio or video is lost, retransmitting that old piece may no longer be useful because new data must continue to arrive.

### Ports

Layer 4 also introduces ports.

An IP address identifies a host, but one host can run many network services at the same time.

For example:

```text
Web browser
SSH
DNS
Email
Teams
```

Ports allow the operating system to identify which network communication belongs to which service or connection.

This can be compared to sending mail.

The IP address identifies the building, while the port helps identify where inside that building the message needs to go.

A connection may look like:

```text
192.168.1.50:53124 → 203.0.113.10:443
```

In this example:

```text
192.168.1.50
```

is the source IP address.

```text
53124
```

is an source port.

```text
203.0.113.10
```

is the destination IP address.

```text
443
```

is the destination port used by HTTPS.

When a client creates a connection, the operating system commonly assigns an source port to that connection.

Ports are commonly divided into ranges:

```text
0-1023
Well-known ports

1024-49151
Registered ports

49152-65535
Dynamic / private ports
```

A network flow can commonly be identified using:

```text
Source IP
Source port
Destination IP
Destination port
Protocol
```

Together these values are often called a **5-tuple**.

The main questions at Layer 4 are:

> Which communication should receive this data?

and:

> How should this data be transported?

## Layer 5 - Session

The Session layer describes the establishment, maintenance, synchronization, and termination of communication sessions between applications.

A session can be thought of as an ongoing conversation rather than a single isolated exchange.

Its purpose is to help both sides maintain the state of communication.

Conceptually:

```text
Session established
        ↓
Communication maintained
        ↓
Data exchanged
        ↓
Synchronization if required
        ↓
Session terminated
```

In modern networking, Layer 5 responsibilities are often handled directly by applications, libraries, or other protocols rather than by a clearly separated Session layer.

This is one reason the TCP/IP model combines several upper OSI layers together.

## Layer 6 - Presentation

The Presentation layer is responsible for ensuring that data is represented in a form both sides can understand.

It may be responsible for functions such as:

* data formatting,
* encoding,
* translation,
* compression,
* encryption,
* decryption.

Not every communication uses compression or encryption.

These functions are used when required by the application or protocol.

The main question at Layer 6 is:

> Can both sides interpret the data in the same way?

## Layer 7 - Application

The Application layer provides network services directly to applications.

It defines protocols applications use to communicate across the network.

The application itself should not necessarily be considered Layer 7. Instead, applications use Layer 7 protocols.

Examples include:

* HTTP and HTTPS,
* DNS,
* SMTP,
* SSH,
* FTP.

For example, a web browser uses HTTP or HTTPS to communicate with web servers.

The main question at Layer 7 is:

> Which network service does the application require and which protocol does it use?

## TCP/IP Model

The TCP/IP model describes network communication using fewer layers than the OSI model.

A common four-layer TCP/IP model consists of:

```text
Application
Transport
Internet
Network Access
```

The OSI layers can be mapped approximately to TCP/IP:

```text
OSI                     TCP/IP

7 Application      ┐
6 Presentation     ├── Application
5 Session          ┘

4 Transport        ─── Transport

3 Network          ─── Internet

2 Data Link        ┐
1 Physical         ┴── Network Access
```

The TCP/IP model is more closely related to the way networking technologies and protocols are implemented in real environments.

The OSI model separates some responsibilities more strictly, making it especially useful for learning and troubleshooting.

In real applications, the responsibilities described by OSI Layers 5, 6, and 7 are often handled together by the application and supporting libraries.

For infrastructure administrators, Layers 1 through 4 are often especially important when investigating basic connectivity problems.

This does not mean problems cannot occur at higher layers.

Issues involving:

* DNS,
* TLS,
* HTTP,
* proxies,
* authentication,
* application configuration,

can also prevent communication from working even if the lower layers are functioning correctly.

### Five-Layer Interpretation

Some materials use a five-layer networking model:

```text
Application
Transport
Network
Data Link
Physical
```

This is not necessarily a contradiction.

It commonly represents the TCP/IP Network Access layer as two separate layers:

```text
Network Access
    ↓
Data Link
Physical
```

## Encapsulation and Decapsulation

As data moves down through the networking layers, each layer adds information required to perform its responsibilities.

This process is called **encapsulation**.

Each layer adds standardized metadata that the corresponding layer on the receiving system understands.

This metadata helps describe:

* how the data should be processed,
* where the data should go,
* which protocol is contained inside,
* how the data should be interpreted.

Conceptually:

```text
Application Data
        ↓
Transport information added
        ↓
Segment / Datagram
        ↓
IP information added
        ↓
Packet
        ↓
Layer 2 information added
        ↓
Frame
        ↓
Bits / Physical signal
```

At the receiving system, the process happens in reverse.

This is called **decapsulation**.

Each layer:

1. reads the information intended for it,
2. processes that information,
3. removes or interprets its encapsulation,
4. passes the remaining payload to the next layer.

Conceptually:

```text
Physical signal
        ↓
Bits
        ↓
Frame
        ↓
Packet
        ↓
Segment / Datagram
        ↓
Application Data
```

Different protocols contain fields that indicate what protocol or data is encapsulated inside them.

Examples include:

```text
Ethernet
→ EtherType

IPv4
→ Protocol field

IPv6
→ Next Header

TCP / UDP
→ Source and destination ports
```

This allows each layer to understand what should happen with the data next.

## Data Names at Different Layers

The same underlying application information is described differently depending on which layer we are discussing.

Common terminology includes:

```text
Application
→ Data

Transport
→ TCP Segment
→ UDP Datagram

Network
→ Packet

Data Link
→ Frame

Physical
→ Bits / Signals
```

Using the correct terminology helps identify which part of communication is being discussed.

For example, saying that an Ethernet frame is incorrect immediately points toward Layer 2.

Talking about TCP segments points toward Layer 4.

This helps narrow the troubleshooting area and makes communication between administrators more precise.

## Network Devices and OSI Layers

Different network devices are commonly associated with different layers.

### Hub

```text
Layer 1
```

A hub does not understand the content of the traffic.

It acts primarily as a repeater, receiving a signal and repeating it through other ports.

### Switch

```text
Layer 2
```

A switch understands Ethernet frames and MAC addresses.

It learns where MAC addresses are located and forwards frames through appropriate ports.

### Router

```text
Layer 3
```

A router receives traffic through Layers 1 and 2, but its primary forwarding decision is based on Layer 3 information.

It examines the destination IP address and uses its routing table to determine where the packet should go next.

### Firewall

A firewall does not necessarily belong to only one OSI layer.

Basic firewall decisions may use information such as:

```text
Source IP
Destination IP
Protocol
Source port
Destination port
```

This primarily involves Layers 3 and 4.

More advanced firewalls may also inspect Layer 7 information such as:

* HTTP,
* DNS,
* TLS,
* application identity,
* URLs,
* users,
* content.

Modern firewalls therefore commonly operate across multiple layers.

## Practical Example - Opening a Website

Consider a user opening:

```text
https://example.com
```

The exact process depends on the protocols and technologies being used, but the communication can be simplified as follows.

### 1. Name Resolution

The workstation needs to determine the IP address associated with the website.

It checks available local resolver information and DNS cache.

If the address is not already known, the workstation queries a DNS resolver.

The DNS response provides the destination IP address.

### 2. Application Communication

The browser prepares the request using an application protocol such as HTTPS.

Because HTTPS is being used, TLS is used to protect the communication.

Compression may also be used depending on the protocol and content.

### 3. Transport

The communication requires an appropriate transport protocol.

For HTTPS, this may involve TCP, or other modern transport mechanisms depending on the protocol version being used.

Transport-layer information such as ports is added.

### 4. IP Communication

The workstation creates the Layer 3 packet containing the destination IP address.

It checks its local network configuration and routing table to determine whether the destination is:

* on the local network,
* or on a remote network.

For an external website, the destination will normally be remote.

The workstation therefore needs to send the traffic toward its default gateway.

### 5. Local Layer 2 Delivery

The workstation determines the Layer 2 address of the gateway.

For IPv4 this commonly involves ARP.

For IPv6, Neighbor Discovery is used.

The workstation creates an Ethernet frame similar to:

```text
Source MAC:
Workstation

Destination MAC:
Default Gateway
```

The IP packet is placed inside this frame.

### 6. Physical Transmission

The frame is converted into the physical representation required by the transport medium.

This may involve:

* electrical signals,
* radio communication,
* optical signals.

### 7. Switching

A switch receives the frame and examines the destination MAC address.

It checks its MAC address table and forwards the frame toward the port where the gateway is reachable.

### 8. Routing

The router receives the frame.

It removes the Layer 2 encapsulation and examines the destination IP address.

It checks its routing table and determines the appropriate next hop or outgoing interface.

A new Layer 2 frame is created for the next link.

The packet is then forwarded.

This process may happen through multiple routers:

```text
Router
    ↓
Remove current Layer 2 frame
    ↓
Inspect destination IP
    ↓
Determine next hop
    ↓
Create new Layer 2 frame
    ↓
Forward packet
```

The Layer 2 frames change between network links while the packet continues toward its IP destination.

### 9. Destination

Eventually the communication reaches the destination system.

The receiving system performs decapsulation.

Conceptually:

```text
Signal
    ↓
Frame
    ↓
Packet
    ↓
Transport data
    ↓
Application data
```

The server processes the request and prepares a response.

That response is encapsulated and sent back through the network.

The client receives it, performs decapsulation, and passes the application data to the browser.

The browser can then process the response and present the website to the user.

## Using Network Models for Troubleshooting

One of the most useful reasons to understand network models is troubleshooting.

Instead of randomly checking different systems, an administrator can investigate communication layer by layer.

A useful approach is to start from the bottom.

### Layer 1

Check whether physical communication is possible.

Examples:

* Is the cable connected?
* Is the connector damaged?
* Is the fiber clean?
* Is there wireless signal?
* Is the interface physically up?
* Are link indicators present?

### Layer 2

Check whether communication on the local network works correctly.

Examples:

* Is the network interface working?
* Is the device in the correct VLAN?
* Is the switch port configured correctly?
* Is the expected MAC address visible?
* Is ARP or Neighbor Discovery working?

### Layer 3

Check IP connectivity.

Examples:

* Does the workstation have a valid IP address?
* Is the subnet mask or prefix correct?
* Is the default gateway configured?
* Is the routing table correct?
* Can the gateway be reached?
* Can remote IP addresses be reached?

A loopback test such as:

```bash
ping 127.0.0.1
```

tests the local TCP/IP stack. It does not test communication across the physical network.

### Layer 4

Check transport communication.

Examples:

* Is the required TCP or UDP port reachable?
* Can the TCP connection be established?
* Are connections being reset?
* Are packets being dropped by a firewall?

### Higher Layers

If Layers 1 through 4 are working, investigate higher-level services.

Examples:

* DNS,
* TLS,
* HTTP,
* proxy configuration,
* authentication,
* application configuration,
* security policies.

This creates a logical troubleshooting workflow:

```text
Problem
    ↓
Identify affected communication stage
    ↓
Identify corresponding layer
    ↓
Test that layer
    ↓
Move higher or lower only when required
```

A user may simply report:

> The internet is not working.

But that description does not identify the actual problem.

The issue could be:

```text
Layer 1
Broken cable

Layer 2
Incorrect VLAN

Layer 3
Missing default gateway

Layer 4
Blocked TCP port

Higher layer
Broken DNS resolution
```

Understanding the layers helps reduce the time required to find the actual cause.

## Key Takeaways

Every networking layer is responsible for a different part of communication.

Network models allow us to understand the path data follows instead of treating networking as one large black box.

The OSI model is especially useful as an educational and troubleshooting framework.

The TCP/IP model more closely reflects how protocols are grouped and implemented in real networks.

Data is encapsulated while moving down through the layers and decapsulated while moving back up.

Different layers use different terminology:

```text
Bits
Frames
Packets
Segments / Datagrams
Application Data
```

Layer 2 mainly deals with communication across the local network link, while Layer 3 allows communication between different networks.

Most importantly, understanding network models helps identify **where a problem is occurring**.

The purpose is not simply to memorize:

```text
Layer 1
Layer 2
Layer 3
...
```

The important skill is being able to ask:

> Which layer is responsible for this function, and which layer should I investigate when it stops working?

Recognizing this can significantly reduce troubleshooting time because instead of searching everywhere, we know where to start looking.
